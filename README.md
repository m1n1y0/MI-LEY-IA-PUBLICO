# MI-LEY-IA

Proyecto para conservar las dos leyes originales y el tercer componente operativo, y comprobar su aplicación mediante una secuencia documentada.

## Arquitectura vigente: componentes 1–2–3

1. **MI LEY** — primera ley.
2. **LEY DE EFICACIA, RIGOR Y RESOLUCIÓN** — segunda ley.
3. **DF-IMIA — Diagrama de Flujo Idioma Máquina IA** — tercer componente operativo de aplicación y comprobación; no es una tercera ley.

La secuencia base es **1 → 2 → 3**. Cada posición determina qué componente se aplica. Si una secuencia de comprobación contiene repeticiones, cada aparición debe ejecutarse y registrarse por separado. La guía de comprobación debe derivarse del contenido auténtico del componente aplicado, no de una lista inventada.

El **prompt escueto queda excluido**: fue una prueba puntual, no es ley, componente vigente ni documento que deba conservarse en el sistema definitivo.

## Organización

- `00_ORIGINALES/`: textos fuente íntegros de las dos leyes; se conservan literalmente.
- `03_SISTEMA/`: arquitectura vigente y DF-IMIA.
- `experimentos/`: protocolos, hipótesis, pruebas, resultados y errores.
- `versiones/`: versiones evaluadas y aprobadas.
- Rama `main`: referencia estable.
- Rama `experimentos`: espacio de trabajo experimental.

## Flujo de trabajo

1. Preservar los textos fuente originales sin cambios.
2. Aplicar la secuencia indicada, respetando el orden y las repeticiones.
3. Generar para cada paso una lista de comprobación basada en el texto fuente correspondiente.
4. Registrar entrada, acción, evidencia, resultado, error y corrección.
5. Repetir la auditoría cuando haya una corrección.
6. Comparar resultados antes de declarar una validación.
7. Integrar cambios en la referencia estable solo con aprobación expresa.
